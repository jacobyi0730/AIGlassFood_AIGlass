# 05. Food 앱과 서버 통신 구현 Task

작성일: 2026-08-19  
대상 프로젝트: `AIGlassFood`, `FoodServer`  
기획서: `Docs/Food기획.md`  
선행 Task: `01. Food 앱 기능 구현 Task`, `03. PC 로컬 서버 프로젝트 생성 및 설정 Task`, `04. 서버와 NVIDIA Nemotron 통신 구현 Task`

## 목적

Android 앱이 촬영 이미지와 수정 가능한 프롬프트를 PC 로컬 서버에 전송하고 결과 또는 오류를 단일 화면 상태에 반영하게 한다.

## 작업 항목

- [ ] `RecipeApiClient`, `RecipeRepository`와 전송/응답 DTO를 추가한다.
- [ ] HTTP 및 JSON 라이브러리를 버전 카탈로그와 앱 의존성에 추가한다.
- [ ] 서버 base URL을 BuildConfig 또는 개발자 설정에서 변경할 수 있게 하고 소스에 개인 PC IP를 고정하지 않는다.
- [ ] `INTERNET` 권한과 로컬 HTTP 개발 통신에 필요한 Android 네트워크 보안 설정을 최소 범위로 적용한다.
- [ ] 촬영 이미지 URI를 안전하게 읽어 multipart 이미지 파트로 변환한다.
- [ ] `prompt`와 기본 `language=ko-KR`를 multipart 텍스트 파트로 전송한다.
- [ ] 요청 전 이미지와 프롬프트를 재검증하고 요청 중 중복 호출을 차단한다.
- [ ] 성공 응답의 `recipeText`를 화면 상태에 반영한다.
- [ ] 4xx 검증 오류, 서버 5xx/NVIDIA 오류, 연결 거부, timeout, 응답 파싱 실패를 사용자용 메시지로 매핑한다.
- [ ] 요청 취소와 ViewModel 수명 주기를 연동한다.
- [ ] 서버 주소 저장 시 API Key 등 비밀 값 입력 기능을 앱에 추가하지 않는다.
- [ ] mock 서버를 사용해 multipart 요청 내용과 성공/실패 응답 매핑을 테스트한다.

## 완료 조건

- [ ] 실제 촬영 이미지, 사용자가 수정한 프롬프트, 언어 값이 API 계약대로 서버에 전달된다.
- [ ] 서버 성공 응답은 레시피 결과 영역에 표시되고 즉시 TTS 재생에 사용할 수 있다.
- [ ] PC 서버에 연결할 수 없을 때 IP, 포트, 동일 Wi-Fi 확인 안내가 표시된다.

## 개발 메모

- `localhost`는 Android 기기 자신을 가리키므로 실기기에서는 PC의 같은 Wi-Fi 사설 IP를 서버 주소로 사용한다.
- Android 9 이상에서 평문 HTTP는 기본 제한될 수 있으므로 개발 서버에 대해서만 좁은 범위의 네트워크 보안 설정을 사용하고 운영 환경에는 HTTPS를 사용한다.
- 이미지와 프롬프트는 사용자가 `레시피 조회`를 누른 시점에만 전송한다.
