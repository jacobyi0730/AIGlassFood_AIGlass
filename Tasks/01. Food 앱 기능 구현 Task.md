# 01. Food 앱 기능 구현 Task

작성일: 2026-08-19  
대상 프로젝트: `AIGlassFood`  
기획서: `Docs/Food기획.md`  
선행 Task: 없음

## 목적

기존 카메라, STT, TTS 기능을 하나의 레시피 생성 흐름으로 통합하고 화면에서 사용할 상태와 이벤트를 제공한다.

## 작업 항목

- [ ] 기존 `CameraViewModel`, `MicrophoneTestViewModel`, `SpeakerTestViewModel`과 각 컨트롤러의 재사용 범위를 정리한다.
- [ ] `food/camera`, `food/microphone`, `food/speaker`, `food/recipe`, `food/ui` 기준으로 패키지 구조를 정리한다.
- [ ] `FoodRecipeViewModel`과 `FoodRecipeUiState`를 추가한다.
- [ ] UI 상태에 안경 등록 여부, 카메라 세션, 촬영 이미지, STT 부분/최종 결과, 요청 진행 여부, 레시피 결과, TTS 상태, 오류를 포함한다.
- [ ] Compose 상태에는 대용량 `ByteArray`를 보관하지 않고 촬영 이미지 `Uri` 또는 repository 내부 캐시를 사용한다.
- [ ] DAT 카메라 세션 시작, 미리보기, 이미지 촬영, 다시 촬영 흐름을 Food 상태에 연결한다.
- [ ] Ray-Ban Meta 후보 Bluetooth 입력 장치를 확인한 후 Android `SpeechRecognizer`를 시작한다.
- [ ] `음성 시작`과 `음성 종료` 이벤트, 부분 STT 결과, 최종 STT 결과를 구현한다.
- [ ] 최종 STT 결과를 편집 가능한 `promptText`에 반영하고 초기화 이벤트를 구현한다.
- [ ] 촬영 이미지 또는 프롬프트가 없을 때 레시피 요청을 차단하고 사용자 조치가 포함된 오류를 반환한다.
- [ ] 서버에서 받은 `recipeText`를 저장하고 이전 결과와 요청 오류 상태를 일관되게 초기화한다.
- [ ] 레시피 TTS 재생과 중지 이벤트를 구현하고 현재 Bluetooth 미디어 출력 상태를 표시한다.
- [ ] ViewModel 종료 시 카메라 세션, STT, TTS 및 관련 리소스를 안전하게 해제한다.
- [ ] 기능별 상태 전이와 입력 검증에 대한 단위 테스트를 추가한다.

## 완료 조건

- [ ] 촬영 → STT → 프롬프트 수정 → 요청 준비 → 결과 저장 → TTS 재생의 상태 전이가 한 ViewModel 흐름으로 동작한다.
- [ ] 안경 마이크가 감지되지 않은 상태에서 휴대폰 마이크로 STT가 시작되지 않는다.
- [ ] 화면 재구성 중 촬영 이미지 URI, 프롬프트, 레시피 결과가 불필요하게 소실되지 않는다.

## 개발 메모

- 기존 구현을 삭제하기 전에 Food 흐름에서 재사용 가능한 컨트롤러와 장치 모니터를 우선 분리한다.
- `ByteArray`는 Compose 상태 비교에 불리하므로 파일 `Uri` 또는 repository 내부 캐시로 관리한다.
- DAT SDK에 마이크·스피커 전용 capability가 있다고 가정하지 않는다.
